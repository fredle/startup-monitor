# Startup Monitor

Watch your PC start up: what has launched, what is still to come, and how long until it is usable.

A Windows micro app generated by app-factory. The spec is in `SPEC.md`.

## Twin app - every change goes to both

This app has a twin, **Ready Yet** (`C:\devel\code\ready-yet`): the same app under
another name and skin. Every feature, fix or behaviour change made here must
also be made there, and the other way round.

- The two share every file under `src/` except `src/brand.rs` (name and ids)
  and `src/theme.rs` (the skin), and `Cargo.toml` from `[dependencies]` on.
- Never write the app's name or ids anywhere else: use `crate::brand::NAME`
  and the other `brand` constants. Colours, shapes and window marks belong
  in `theme.rs`.
- After changing shared files here, run
  `C:\devel\code\app-factory\tools\sync-twins.ps1 startup-monitor -From` to copy them
  across, then build, test and commit both. `factory.ps1 release` refuses
  while the twins differ, so release both.
- A change to `theme.rs` that is a feature rather than a look (a new painted
  widget the shared code calls) needs the same function in the twin's
  `theme.rs`, in that app's style.

## Stack (fixed - do not change)

- Rust 2024, `eframe`/`egui` 0.36 (glow), single exe, `#![windows_subsystem = "windows"]`.
- Velopack for install and self-update from GitHub Releases. Released by
  `.github/workflows/release.yml` on `v*` tags: Trusted Signing, GitHub
  Release, blob mirror, Microsoft Store submission.
- eframe 0.36's `App` trait method is `fn ui(&mut self, ui: &mut egui::Ui, frame: &mut eframe::Frame)`,
  and panels take that `Ui` (`CentralPanel::default().show(ui, ...)`).
  Side/top/bottom panels are `egui::Panel::left/right/top/bottom(id)` -
  there is no `TopBottomPanel` or `SidePanel` in 0.36.

## Factory-owned files - leave as-is

- `src/update.rs`, `src/main.rs` (only add `mod` lines), `src/shots.rs`,
  `.github/workflows/release.yml`, `build.rs`, and everything under
  "Factory plumbing" in `assets/make-icon.ps1`.
- The footer in `src/app.rs` (auto-update toggle + version) must stay.

## Design - the app must look designed, not generated

People judge a Store app by its screenshots and icon before they read a
word. A default-egui window, or the look of a generic AI-made tool, loses the
install. These rules are as binding as the spec.

**Use the theme.** `src/theme.rs` is the house look: light and dark palettes,
Segoe UI, cards, one filled primary button, quiet secondary buttons, pills,
a segmented control, line-drawn icons. Build the window from those pieces and
add new painted pieces to `theme.rs` when the app needs them. Never use a
bare `ui.button`, `ui.heading`, `ui.separator` or `ui.group`, and never set a
colour, size or radius in `app.rs`: take it from the palette and constants.

**Give the app its own accent.** Change the accent values in both palettes
(`accent`, `accent_text`, `on_accent`, `accent_soft`) to one hue that suits
what the app does, and use the same hue for the icon tile. Do not reuse the
template's blue or another factory app's colour. The contrast test in
`theme.rs` must pass.

**Layout.**
- One clear primary action per screen, as the only filled button. Everything
  else is secondary or a text link.
- Group related controls in cards with a short section label. Align to a
  grid: 16 px window margin, 12 px between cards, 8 px between controls.
- Size the window to its content. No large empty areas, no scrolling for the
  main task, nothing clipped at the minimum size.
- Write an empty state that says what to do, with a drawn motif from the
  app's subject (not a grey sentence in the middle of nothing).
- Show state where the user is looking: running, done and failed each look
  different (colour, pill, progress), not just a changed label.
- Numbers get proper inputs with units next to them, not free text boxes.

**Things that mark an app as machine-made - never ship them.**
- Emoji or symbol characters as icons (✓ ▶ ⚙ 📁 and the like). Draw icons
  with `theme::paint_icon`, adding to the `Icon` enum.
- Purple-to-blue gradients, glows, drop shadows, glass or neon effects.
- Centred everything; a heading that repeats the window title; a tagline or
  marketing sentence inside the app.
- Every control visible at once in one long form. Put rarely used options
  behind a "More options" disclosure.
- Title Case On Every Label, exclamation marks, "Welcome to...", "Simply...",
  "Powerful", "Seamless", "Effortless".
- Labels that explain the obvious, and help text under every field.

**Words.** Sentence case. Short, plain, specific: "Start clicking", not
"Start"; "Stops after 500 clicks", not "Limit enabled". Say what happened and
what to do in errors. No jargon the user did not bring.

**Look at it.** `cargo run --release -- --shots target/shots` writes a PNG of
each scene set up in `App::show_scene` (add `--theme dark` for dark). Read
those PNGs, judge them as a stranger browsing the Store would, fix what
looks wrong, and repeat until both themes hold up. Check alignment, spacing,
truncated text, contrast and what the eye lands on first.

## Icon

`assets/make-icon.ps1` draws the app icon and the Store logo. Replace
`Draw-Mark` with one simple white mark that says what the app does (a
cursor for a clicker, sound bars for audio), and set the two tile colours to
the app's accent. No letters or initials, no thin lines, at most three
shapes. Run `pwsh -NoProfile -File assets/make-icon.ps1`, read
`assets/icon-preview.png` and `assets/icon-preview-32.png`, and redraw until
the mark is centred, balanced and still recognisable at 32 px. The script
also writes `assets/icon-64.rgba`, which `src/app.rs` compiles in as the
window icon (`window_icon()`, keep it), so rebuild after redrawing.

## Store screenshots

`App::show_scene` sets up 3 or 4 made-up but believable states (set
`SHOT_SCENES` to match): the app ready with real-looking content, mid-task,
finished, and one that shows the feature the leaders lack. Never an empty
window first. Write `store/shots.json` with a caption for each, in order:

```json
{ "accent": "#RRGGBB",
  "scenes": [ { "name": "1-ready", "title": "Up to six words", "body": "One plain sentence." } ] }
```

The factory runs screenshot mode and composes the Store images from it.

## Rules for building the app

- Implement the spec in `src/app.rs` and new modules. Keep it small and
  dependency-light; every new crate needs a reason.
- Persist state under `settings::data_dir()` (%LOCALAPPDATA%\StartupMonitor).
- No network calls except the update check, unless the spec requires them.
- No telemetry, no accounts, no admin rights.
- Put logic that can be tested in plain functions and cover it with
  `#[cfg(test)]` unit tests. `cargo build --release` and `cargo test` must
  pass with no warnings.
